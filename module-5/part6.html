Binary and Count Outcomes in Experiments

NoteThe Outcome Type Question

What kind of outcome variable does your experiment produce? Choices (opted in / opted out), counts (number of risky choices out of 10), or proportions (share of gambles taken) are not continuous normal outcomes. Fitting a linear model to them misspecifies the DGP.

What goes wrong with a linear mixed model? Predicted probabilities can fall outside [0, 1]. The Gaussian model imposes the wrong mean-variance relationship and does not respect the binary or count DGP. Predicted probabilities can fall outside [0, 1], and inferences can be misleading, especially near the boundaries.

What is the fix? Generalized Linear Mixed Models (GLMMs) — logistic for binary, Poisson or negative binomial for counts — with the same random effects structure as the continuous case.

When Experimental Outcomes Are Not Continuous

JDM experiments frequently produce non-continuous outcomes:

  • Binary choices: Did the participant opt into the default? Choose the risky gamble? Adopt the recommended product?
  • Counts within a block: How many of 10 gambles did the participant accept? How many disclosure warnings did the consumer respond to?
  • Binary flags: Did the household enroll in automatic savings? Did the participant choose the gain-framed option?

Fitting a standard linear mixed model to these outcomes is not just statistically suboptimal — it misspecifies the data-generating process. The probability of opting in cannot genuinely be negative, but a linear model will predict it below zero for low-baseline participants. The count of risky choices in a 10-gamble block is bounded above at 10, but a linear model will sometimes predict above that bound.

Generalized Linear Mixed Models (GLMMs) handle this correctly. The nesting structure — observations within participants, participants possibly nested in groups or crossed with stimuli — is modeled with the same random effects as before. The difference is the link function (which maps the linear predictor to the outcome scale) and the distributional family (which describes how the outcomes are distributed given the mean).

What Is a Link Function? A Plain-Language Visual

Before diving into models, it helps to see what a link function actually does. The link function is what converts the linear predictor (a number that can take any value, positive or negative) into the scale of the outcome (which has a restricted range — a probability must be between 0 and 1; a count must be non-negative).

Code 
x_seq <- seq(-3.5, 3.5, length.out = 200)

df_links <- bind_rows(
  # Identity link (linear model): predicted value = linear predictor (no constraint)
  tibble(
    linear_predictor = x_seq,
    predicted        = x_seq,
    link  = "Identity link\n(Linear model — continuous outcome)",
    note  = "No constraint: predicted value\ncan be negative or > 1"
  ),
  # Logit link (logistic model): maps log-odds to probability ∈ (0, 1)

    linear_predictor = x_seq,
    predicted        = plogis(x_seq),
    link  = "Logit link\n(Logistic model — binary 0/1 outcome)",
    note  = "S-curve: predicted stays in (0, 1)\nSlope flattest at extremes"
  ),
  # Log link (Poisson model): maps log-rate to non-negative count
  tibble(
    linear_predictor = x_seq,
    predicted        = exp(x_seq),
    link  = "Log link\n(Poisson model — count outcome \u2265 0)",
    note  = "Exponential: predicted always positive\nVariance scales with mean"
  )
) |>
  mutate(link = factor(link, levels = unique(link)))

ggplot(df_links, aes(x = linear_predictor, y = predicted)) +
  geom_line(linewidth = 1.4, color = "#1e3a5f") +
  geom_hline(data = tibble(link = factor("Logit link\n(Logistic model — binary 0/1 outcome)",
                                          levels = levels(df_links$link)),

                                          levels = levels(df_links$link)),

  geom_hline(yintercept = 0, linetype = "dotted", color = "#aaa", linewidth = 0.5) +
  facet_wrap(~ link, scales = "free_y", ncol = 3) +
  labs(
    title    = "Three link functions: how the linear predictor maps to the outcome scale",
    subtitle = "Red dashed lines = constraints on the outcome (0/1 for binary; \u22650 for counts)\nThe curve between the linear predictor (x-axis) and predicted value (y-axis) IS the link function",

Why this matters for interpretation:

  • The identity link (linear model) produces a straight line: a one-unit increase in X always shifts the predicted outcome by the same amount (\(\beta_1\)), regardless of where you are on the scale.
  • The logit link produces an S-curve: the same log-odds change (\(\beta_1\)) produces a smaller probability change when the baseline probability is near 0 or 1, and a larger change when it is near 0.5. This is why odds ratios do not translate directly to probability differences without knowing the baseline.
  • The log link produces an exponential curve: the same log-rate change (\(\beta_1\)) produces a larger count change when the baseline count is high. This is why Poisson models produce rate ratios, not count differences.

The experimental implication: in a GLMM, the fixed effect \(\beta_1\) lives on the link scale (log-odds or log-rate), not the outcome scale. Always report both the link-scale estimate (for comparability and meta-analysis) and the back-transformed predicted outcome (for interpretability).

Part 1: Binary Outcomes — Logistic Mixed Model

The model

For a binary outcome \(Y_{ij} \in \{0,1\}\) at trial \(i\) for participant \(j\) in a within-subjects design:

\[\text{logit}\bigl(P(Y_{ij} = 1)\bigr) = \beta_0 + u_{0j} + \beta_1 \cdot \text{condition}_{ij}\]

The random intercept \(u_{0j}\) captures stable individual differences in baseline response tendency — some participants are generally more risk-accepting or more opt-in-prone than others. Omitting this term ignores the within-person dependence from repeated measurements, deflating standard errors and inflating Type I error.

Example: Loss framing and risky financial choices

We simulate a within-subjects framing experiment. 80 participants each evaluate 16 gambles — half framed as potential gains (“Win $200 with probability 0.5; win nothing otherwise”), half framed as potential losses (“Lose nothing with probability 0.5; lose $200 otherwise”). The outcome is binary: did the participant accept the gamble (1) or decline (0)?

The true framing effect is an odds ratio of 1.8: loss-framed gambles have 80% higher odds of acceptance (consistent with loss aversion driving risk-seeking under losses). Participants differ substantially in their baseline risk tolerance.

Code 
n_participants <- 80
n_trials_each  <- 8   # 8 gain-framed + 8 loss-framed trials per person

u0_person <- rnorm(n_participants, 0, 1.2)   # individual risk tolerance differences

df_gamble <- expand_grid(
  participant = 1:n_participants,
  framing     = c("gain", "loss"),
  trial       = 1:n_trials_each
) |>
  mutate(
    u0            = u0_person[participant],
    framing_dummy = as.integer(framing == "loss"),
    log_odds      = -0.5 + u0 + 0.59 * framing_dummy,   # log(1.8) ≈ 0.59
    prob          = plogis(log_odds),
    accepted      = rbinom(n(), 1, prob),
    participant   = factor(participant),
    framing       = factor(framing, levels = c("gain", "loss"))
  )

df_gamble |>
  group_by(framing) |>
  summarise(
    n_trials       = n(),
    acceptance_rate = mean(accepted),
    .groups = "drop"
  ) |>
  knitr::kable(digits = 3, caption = "Observed gamble acceptance rates by framing condition")

Translating to the probability scale

Odds ratios are the correct internal currency of the logistic model — but they are unintuitive. Report predicted probabilities for audiences not comfortable with odds:

Code 
preds_gamble <- ggpredict(m_gamble, terms = "framing", type = "fixed")

plot(preds_gamble) +
  scale_color_manual(values = c("#1e3a5f", "#e63946")) +
  labs(
    title    = "Predicted gamble acceptance by framing condition",
    subtitle = "Marginal predictions (averaging over individual risk tolerance)",
    x        = "Framing condition",
    y        = "Predicted probability of accepting gamble"
  ) +
  theme_minimal(base_size = 13)

The nonlinearity of marginal effects

A constant odds ratio translates to different probability differences depending on the baseline probability. The same OR of 1.8 produces a larger absolute increase in acceptance when the baseline probability is 0.5 than when it is near 0 or 1. This means:

  • Sub-populations with different baseline risk tolerance will show different absolute probability effects of framing — even if the log-odds effect is homogeneous.
  • A single marginal probability difference from a regression table is only a population-average summary, not a universal statement about all participants.
Code 
tibble(
  baseline_logodds = seq(-3, 3, by = 0.25),
  baseline_prob    = plogis(baseline_logodds),
  treatment_prob   = plogis(baseline_logodds + log(1.8)),
  prob_difference  = plogis(baseline_logodds + log(1.8)) - plogis(baseline_logodds)
) |>
  ggplot(aes(x = baseline_prob, y = prob_difference)) +
  geom_line(linewidth = 1.3, color = "#1e3a5f") +
  geom_hline(yintercept = 0, linetype = "dashed", color = "#888") +
  labs(
    title    = "Same log-odds effect → different probability differences by baseline",
    subtitle = "OR = 1.8 (log-odds effect = 0.59). Probability difference peaks near p = 0.5.",
    x        = "Baseline probability of accepting gamble",
    y        = "Probability increase due to loss framing"
  ) +
  scale_x_continuous(labels = scales::percent_format()) +
  scale_y_continuous(labels = scales::percent_format()) +
  theme_minimal(base_size = 13)

Part 2: Bounded and Unbounded Count Outcomes

Know your count type before choosing a model

Not all counts are Poisson. The DGP — how the count was generated — determines the model family.

NoteOutcome Type Audit
Outcome type DGP Correct model Common mistake
Binary single trial Bernoulli(p) Logistic GLMM —
Repeated binary trials per person Bernoulli(p) across trials Logistic GLMM with random intercepts Treating proportions as continuous
Count from a fixed number of trials Binomial(n, p) — bounded at n Binomial GLMM: cbind(k, n−k) Using Poisson (unbounded, wrong DGP)
Unbounded count in a time window Poisson(λ) or NB Poisson/NB GLMM; add offset if exposure differs Using a bounded-count family
Many structural zeros Two-process model Zero-inflated / hurdle Poisson underestimates zeros

The bounded count problem

“Number of risky choices out of 10 gambles” is a bounded count: it ranges from 0 to 10, not 0 to ∞. Generating this with a Poisson distribution and then truncating at 10 is wrong — the Poisson mean-variance relationship (\(\text{Var} = \mu\)) does not hold for bounded data, and the truncation does not correspond to any standard distributional family.

The correct DGP: each of the 10 gambles is a Bernoulli trial — the participant accepts (1) or declines (0). The total count is the sum: \(Y_i \sim \text{Binomial}(n = 10, p_i)\). The corresponding model is a binomial GLMM using cbind(successes, failures) syntax.

The model

\[\text{logit}\bigl(p_{ij}\bigr) = \beta_0 + u_{0j} + \beta_1 \cdot \text{condition}_{ij}\]

where \(p_{ij}\) is the per-gamble acceptance probability for participant \(j\) in block \(i\), and the outcome is \(Y_{ij} \sim \text{Binomial}(10, p_{ij})\). Exponentiating \(\beta_1\) gives an odds ratio for per-gamble acceptance.

Example: Information disclosure and risky choices (bounded count)

We simulate a within-subjects experiment: 60 participants each complete 4 blocks per condition (control vs. disclosure). In each block, they evaluate 10 gambles and choose to accept or decline. The true per-gamble acceptance probability is ~55% in control and ~40% under disclosure (log-odds effect ≈ −0.6, OR ≈ 0.55).

Code 
n_per_cond <- 60
n_blocks   <- 4   # 4 blocks of 10 gambles per condition (within-subjects)

df_risky <- expand_grid(
  participant = 1:n_per_cond,
  condition   = c("control", "disclosure"),
  block       = 1:n_blocks
) |>
  mutate(
    u0          = rnorm(n_per_cond, 0, 0.5)[participant],   # stable individual risk tolerance
    p_risky     = plogis(0.2 + u0 - 0.6 * as.integer(condition == "disclosure")),
    risky_count = rbinom(n(), size = 10, prob = p_risky),   # bounded 0–10: correct DGP
    participant = factor(participant),
    condition   = factor(condition, levels = c("control", "disclosure"))
  )

df_risky |>
  group_by(condition) |>
  summarise(
    n_observations = n(),
    mean_accepted  = mean(risky_count),
    sd_accepted    = sd(risky_count),
    mean_prop      = mean(risky_count / 10),
    .groups = "drop"
  ) |>
  knitr::kable(digits = 3,
    caption = "Risky choices out of 10 gambles per block, by condition. True per-gamble probability: ~55% control, ~40% disclosure.")

When binomial is not enough: beta-binomial overdispersion

The standard binomial GLMM assumes that, after conditioning on the random intercept, all 10 trials within a block are independent with the same \(p\). In practice there can be extra-binomial variability — within a block a participant may be in a streak, or their threshold may shift partway through. This makes variance exceed the binomial prediction.

The beta-binomial family handles this: it models \(p\) itself as random, adding a dispersion parameter that allows variance beyond the binomial.

Code 
m_risky_bb <- glmmTMB(
  cbind(risky_count, 10 - risky_count) ~ condition + (1 | participant),
  data   = df_risky,
  family = betabinomial
)

tibble(
  Model = c("Binomial GLMM", "Beta-binomial GLMM"),
  AIC   = c(AIC(m_risky), AIC(m_risky_bb)),
  Notes = c("Assumes within-block trials are exchangeable",
            "Allows per-block overdispersion")
) |>
  knitr::kable(digits = 1,
    caption = "Model comparison. Use beta-binomial if there is overdispersion (streaky choices, shifting thresholds).")
Model comparison. Use beta-binomial if there is overdispersion (streaky choices, shifting thresholds).

When unbounded counts are the right outcome

If your count has no ceiling — number of times a participant checked their savings app in a week, number of optional information requests, number of financial decisions logged — use Poisson or negative binomial:

Code 
n_par_w  <- 60
n_weeks  <- 4

df_checkups <- expand_grid(
  participant = 1:n_par_w,
  condition   = c("control", "nudge"),
  week        = 1:n_weeks
) |>
  mutate(
    u0          = rnorm(n_par_w, 0, 0.5)[participant],
    log_mu      = 1.5 + u0 - 0.43 * as.integer(condition == "control"),
    mu          = exp(log_mu),
    phi         = rgamma(n(), shape = 3, rate = 3),
    check_count = rpois(n(), mu * phi),
    participant = factor(participant),
    condition   = factor(condition, levels = c("control", "nudge"))
  )

m_nb_within <- glmmTMB(
  check_count ~ condition + (1 | participant),
  data   = df_checkups,
  family = nbinom2
)

broom.mixed::tidy(m_nb_within, effects = "fixed", exponentiate = TRUE, conf.int = TRUE) |>
  filter(term != "(Intercept)") |>
  select(term, estimate, conf.low, conf.high, p.value) |>
  knitr::kable(digits = 3,
    caption = "Negative binomial GLMM for unbounded weekly check-in count. Rate ratio: nudge vs. control.")

Part 3: Mixed Factorial Designs with Non-Normal Outcomes

Many JDM experiments combine a between-subjects factor (e.g., standard vs. gain-frame disclosure) with a within-subjects factor (e.g., high-stakes vs. low-stakes gamble blocks). When outcomes are binary or counts, GLMMs handle this naturally.

Code 
n_par_mf <- 100   # 50 per between-subjects condition
n_items   <- 4    # items per within-subjects condition

df_mf <- expand_grid(
  participant  = 1:n_par_mf,
  stakes       = c("low", "high"),
  item         = 1:n_items
) |>
  mutate(
    disclosure = ifelse(participant <= 50, "standard", "gain_frame"),
    u0         = rnorm(n_par_mf, 0, 0.9)[participant],
    log_odds   = -0.3
      + u0
      + 0.5 * (stakes == "high")                              # high stakes increases risk-seeking
      + 0.4 * (disclosure == "gain_frame")                    # gain frame shifts toward acceptance
      + 0.3 * (stakes == "high") * (disclosure == "gain_frame"), # interaction
    prob          = plogis(log_odds),
    chose_risky   = rbinom(n(), 1, prob),
    participant   = factor(participant),
    stakes        = factor(stakes, levels = c("low", "high")),
    disclosure    = factor(disclosure, levels = c("standard", "gain_frame"))
  )

m_mf <- glmer(
  chose_risky ~ stakes * disclosure + (1 | participant),
  data   = df_mf,
  family = binomial
)

broom.mixed::tidy(m_mf, effects = "fixed", exponentiate = TRUE, conf.int = TRUE) |>
  select(term, estimate, conf.low, conf.high, p.value) |>
  knitr::kable(
    digits = 3,
    caption = "Mixed factorial GLMM: stakes × disclosure framing on risky choice (odds ratios). Interaction OR > 1 means the disclosure effect is larger under high stakes."
  )

Assumptions

WarningAssumption: Correct Link Function and Distributional Family

Plain-language meaning: The model assumes that log-odds (logistic) or log-count (Poisson/NB) are linearly related to predictors. This is a reasonable default for most JDM outcomes, but the choice of family should match how you believe the outcomes were generated.

What the model is assuming away: The possibility that outcomes cluster near boundaries (very high or very low acceptance rates) in ways the standard logit link fits poorly, or that counts have structural excess zeros (many participants who never accept any gamble).

JDM example: If the gamble task is very easy and all participants accept most gambles (base rate near 0.95), the logit model is working in the nonlinear tails where slight misspecification matters more. A complementary log-log link might fit better.

What a skeptical reviewer might say: “You used a logistic model — but with acceptance rates consistently above 90%, all your odds ratios are in the highly compressed region of the probability scale. Can you verify the link function is appropriate?”

Observable warning sign: Predicted probabilities consistently near 0 or 1; the model struggling to converge; or large odds ratios that translate to tiny probability differences.

What to check: Plot observed proportions against predicted probabilities. For count outcomes, compare the observed distribution of counts to the predicted distribution from the fitted model. Check the dispersion ratio (should be near 1.0 for Poisson; switch to negative binomial if > 1.5).

What claim survives if the assumption is doubtful: The direction of the effect is usually robust. The exact magnitude on the probability scale may be sensitive to the link function when outcomes are near boundaries.

WarningAssumption: No Complete Separation

Plain-language meaning: For logistic models, maximum likelihood estimation requires that both outcome values (0 and 1) occur across the range of predictors. Complete separation — where one condition perfectly predicts the outcome — causes the estimated log-odds to diverge to infinity and standard errors to blow up.

What the model is assuming away: The practical possibility that an experimental manipulation is so strong, or a sample is so small, that one cell has all 0s or all 1s.

JDM example: If all participants in the loss-frame condition declined every gamble (all 0s) and all participants in the gain-frame condition accepted every gamble (all 1s), the logistic model has no finite solution.

What a skeptical reviewer might say: “Your condition-level acceptance rates are 0% and 98% — are your results artifacts of near-complete separation?”

Observable warning sign: Extremely large estimated coefficients (in the hundreds) with enormous standard errors; a warning from glmer() about convergence or Hauck-Donner effects.

What to check: Inspect condition-level contingency tables before fitting. If any cell is empty or near-empty, use Firth’s penalized likelihood (brglm2 package) or Bayesian estimation.

WarningAssumption: Correct Distributional Family for Count Outcomes

Plain-language meaning: Poisson assumes mean = variance. Negative binomial relaxes this, allowing variance > mean (overdispersion). Zero-inflated models further allow excess structural zeros.

What the model is assuming away with Poisson: That individual-level heterogeneity in choice propensity does not create extra variance in counts beyond what a simple rate model predicts.

JDM example: In a repeated gamble task, participants with generally low risk tolerance will contribute many near-zero blocks while participants with high risk tolerance contribute many near-10 blocks. This cross-person heterogeneity creates overdispersion relative to Poisson.

What a skeptical reviewer might say: “The Poisson model assumes variance equals mean for your choice counts, but in a within-subjects design with individual differences, this seems implausible. Did you check for overdispersion?”

Observable warning sign: Dispersion ratio > 1.5; residual variance plots showing systematic patterns.

What to check: Report the dispersion ratio explicitly. If > 1.5, switch to nbinom2 in glmmTMB(). If the count distribution has excess zeros beyond the model prediction, add a zero-inflation component.

WarningAssumption: Sufficient Within-Person Observations for Stable Random Effects

Plain-language meaning: The logistic random intercept is estimated from each participant’s repeated choices. With very few observations per participant (e.g., 2 binary trials), the individual-level log-odds are estimated very imprecisely and the random-effects variance is unstable.

JDM example: In a 2-trial binary choice experiment, each participant contributes only two observations — one per condition. The random intercept for that participant is essentially identified by a single data point. The random-effect variance estimate will be very noisy.

What a skeptical reviewer might say: “With only 4 trials per participant per condition, how reliable are your random-effects estimates?”

What to check: Aim for at least 5–10 binary trials per participant per condition for stable random-effects estimation. With fewer, consider Bayesian estimation (brms) which regularizes the random effects via priors and handles small-cluster GLMMs more stably.

Reviewer Challenge

TipWhat a Reviewer Would Ask

Challenge 1: “Why not just analyze the proportion correct / proportion accepted as a continuous outcome?” Converting binary outcomes to proportions and using a linear model is a common shortcut. It produces approximately correct inference when proportions are in the 0.2–0.8 range, but fails near the boundaries where the probability scale becomes nonlinear. More importantly, the logistic random intercept correctly models the individual differences on the log-odds scale — which is where the DGP actually operates — rather than forcing normal residuals onto a bounded proportion.

Challenge 2: “Your odds ratios are hard to interpret. Can you just report probability differences?” Both should be reported. Odds ratios are the natural effect size from the model (they are constant across baseline probability levels). Marginal probability differences from ggpredict() are easier to communicate but depend on the reference population. Report odds ratios in the model table and predicted probabilities in the figure. State both.

Challenge 3: “Your random intercept variance is large — could the treatment effect be moderated by individual differences?” Yes, and this is worth examining. A large random intercept variance means participants vary a lot in their baseline tendencies. A random slope model — (1 + framing | participant) — tests whether the framing effect itself varies across participants. If it does, reporting a single average effect misses important heterogeneity. The random slope test is the right diagnostic.
