Maximal vs. Parsimonious Random Effects

NoteThe Random Effects Design Question

Which predictors vary within your grouping unit (participant, stimulus, site)? Only those can have a random slope for that unit. A random slope for a between-subjects factor is a model misspecification.

What is the right starting point for confirmatory tests? Start with the maximal theoretically justified structure — every random slope the design can support — then simplify transparently when the data cannot support that structure.

What is the tradeoff? Maximal models protect Type I error but can fail to converge or produce degenerate variance components. Parsimonious models can improve power but inflate Type I error for within-subjects effects. Report all simplification decisions so the preregistered and realized models are distinguishable.

The Debate

In 2013, Barr, Levy, Scheepers, & Tily published an influential paper titled “Random Effects Structure for Confirmatory Hypothesis Testing: Keep It Maximal.” Their argument:

To control Type I error at the nominal level, researchers should include the maximal random effects structure — every random slope that is justified by the experimental design.

In a within-subjects design where every participant sees every condition, you must include a random slope for condition by participants. Omitting this random slope will produce anti-conservative p-values.

Two years later, Matuschek, Kliegl, Vasishth, Baayen, & Bates (2017) pushed back in a paper titled “Balancing Type I Error and Power in Linear Mixed Models.” Their argument:

Maximal models frequently fail to converge or produce degenerate variance components. Over-parameterized models can actually have worse power than well-specified parsimonious models. Use likelihood ratio tests to decide what to include.

Both papers are correct. The question is when each applies.

Why Maximal Models Can Fail

Code 
# Simulate a within-subjects design
# Each participant sees each condition 4 times (trials)
# 40 participants × 3 conditions × 4 trials = 480 observations
# Random effects needed: 40 × 3 = 120 — well below 480
n_participants <- 40
n_conditions   <- 3
n_trials       <- 4

participant_intercepts <- rnorm(n_participants, 50, 8)
# Small (but nonzero) random slopes
participant_slopes     <- rnorm(n_participants, 0, 0.5)

df_within <- expand_grid(
  participant = 1:n_participants,
  condition   = 1:n_conditions,
  trial       = 1:n_trials
) |>
  mutate(
    condition_eff = c(-2, 0, 2)[condition],  # condition effect
    p_slope       = participant_slopes[participant],
    Y = participant_intercepts[participant] + condition_eff +
        p_slope * condition_eff + rnorm(n(), 0, 5),
    participant = factor(participant),
    condition   = factor(condition)
  )

# Maximal model
m_max <- lmer(Y ~ condition + (condition | participant),
              data    = df_within,
              control = lmerControl(optimizer = "bobyqa"))

# Does it converge?
library(performance)
check_convergence(m_max)
[1] TRUE
attr(,"gradient")
[1] 7.545173e-07
Code 
# Parsimonious model (random slope variance is tiny — can drop it)
m_pars <- lmer(Y ~ condition + (1 | participant), data = df_within)
Code 
# Compare: do the p-values differ substantially?
anova(m_pars, m_max)
npar AIC BIC logLik -2*log(L) Chisq Df Pr(>Chisq)
m_pars 5 3045.677 3066.546 -1517.838 3035.677 NA NA NA
m_max 10 3041.815 3083.553 -1510.907 3021.815 13.86175 5 0.0165119

Random Effects Eligibility Table

The first question is not “should I use a random slope?” but “can I use a random slope?” A random slope for predictor X by grouping unit G requires that X varies within G. If X is constant within G, there is no within-G variation to estimate a slope on.

Predictor Varies within participant? Varies within stimulus? Can have by-participant slope? Can have by-stimulus slope?
Within-subjects condition (e.g., framing) ✓ yes ✓ yes (if counterbalanced) ✓ yes ✓ yes
Between-subjects condition (e.g., disclosure arm) ✗ no ✓ yes (if stimuli span conditions) ✗ no — between-subjects ✓ possibly
Trial number (time-within-session) ✓ yes ✓ yes ✓ yes ✓ yes
Stimulus difficulty/valence ✗ no (fixed per stimulus) — (stimulus-level predictor) ✗ no —
Participant-level covariate (age, literacy) ✗ no ✓ yes — ✓ yes

Key rule: If a predictor does not vary within the grouping unit, including a random slope for it either crashes the model or produces a degenerate zero-variance component. The coefficient table in summary() will show a variance estimate of 0 or near 0 for that slope.

A Practical Simplification Workflow

Use this sequence for every confirmatory mixed model:

  1. List all grouping factors — participants, stimuli, sites, advisors, etc.
  2. List all predictors — for each, note whether it varies within each grouping factor (see table above).
  3. Specify the maximal theoretically justified structure — include random slopes for every within-unit predictor; omit for between-unit predictors.
  4. Fit the maximal model with a robust optimizer (e.g., bobyqa).
  5. Check convergence and singularity — isSingular(), performance::check_convergence(), warnings in the console.
  6. If singular or non-convergent: first remove the correlation parameter between random intercept and slope ((1 | G) + (0 + X | G) instead of (X | G)).
  7. If still problematic: remove the random slope with the smallest variance component — but document this as a deviation from the preregistered structure.
  8. Report all simplification decisions, including the likelihood ratio test result that motivated each removal.
WarningWhat “Singular” Means and Why It Matters

isSingular() returns TRUE when one or more variance components are estimated at exactly the boundary of the parameter space (typically: variance = 0, or a correlation = ±1). This is not an error — it is information. It means the data do not support the complexity of the model.

Observable signs of singularity: - Random slope variance estimated at exactly 0.000 - Correlation between random intercept and slope estimated at exactly +1.000 or −1.000 - The lme4 message: “Model is nearly unidentifiable: very large eigenvalue…”

What to do: - First try removing the correlation: (1 | G) + (0 + X | G) instead of (X | G) - If variance is still at zero, use an LRT to test whether the random slope improves fit; if p > .10, drop it and document the decision - Do not use a singular model as the final model without disclosing the singularity

The Decision Framework

The current consensus among methodologists:

NoteWhen to Use Maximal Random Effects

  1. Within-subjects experimental manipulations: For confirmatory tests, start with random slopes for within-subjects factors. Barr et al. (2013) are correct that omitting these inflates Type I error — but only when the data can support the structure. If convergence fails, simplify transparently rather than silently defaulting to a misspecified parsimonious model.

  2. When theory or pilot data suggests heterogeneous effects: If you have prior reason to believe the treatment effect varies substantially across participants, include the random slope.

  3. Large samples: With enough data, complex models converge and the efficiency loss from over-parameterization is small.

NoteWhen to Simplify (Parsimonious)

  1. Convergence failures: If the maximal model does not converge, you must simplify. Start by removing the correlation between random intercept and slope ((1 | participant) + (0 + condition | participant)). Then consider removing the random slope itself.

  2. Degenerate variance components: If the random slope variance is estimated at exactly zero (or very near), it is contributing nothing and can be dropped.

  3. Very small variance components: Use an LRT to test whether the random slope significantly improves fit. If not, the parsimonious model is appropriate.

A Practical Simplification Protocol

Code 
# Step 1: Try the maximal model
m_max_2 <- tryCatch(
  lmer(Y ~ condition + (condition | participant),
       data = df_within, control = lmerControl(optimizer = "bobyqa")),
  warning = function(w) { cat("Warning:", conditionMessage(w), "\n"); NULL }
)

# Step 2: If it fails/has issues, remove correlation first
m_no_corr <- lmer(Y ~ condition + (1 | participant) + (0 + condition | participant),
                  data = df_within)

# Step 3: Test: does the random slope improve fit?
anova(m_pars, m_no_corr)
npar AIC BIC logLik -2*log(L) Chisq Df Pr(>Chisq)
m_pars 5 3045.677 3066.546 -1517.838 3035.677 NA NA NA
m_no_corr 11 3043.815 3089.727 -1510.907 3021.815 13.86175 6 0.0312192
Code 
# If p > 0.05 on the LRT, the random slope does not help — use m_pars
WarningAssumption: The Random Effects Structure Matches the Design

What it means: The random effects you include should reflect the actual nesting structure of your design. A random slope for a between-subjects factor makes no statistical sense (between-subjects factors cannot vary within a subject).

Common mistake: Including a random slope for a between-subjects condition. This will either produce a degenerate model or absorb all variance in a nonsensical way.

How to check: For each predictor, ask: does this variable vary within the grouping unit (participant, stimulus)? If yes, it can have a random slope for that unit. If no (between-subjects), it cannot.

What to do if the maximal model fails: Remove correlation parameters first, then remove slopes with near-zero variance. Document each step and report it in the methods section as a pre-specified or transparent deviation.

Reviewer Challenge

TipWhat a Reviewer Would Ask

Challenge 1: “Barr et al. (2013) say you need to keep the random effects maximal. Why did you simplify?” The Barr et al. recommendation applies specifically to the maximal theoretically justified structure. If the random slope variance was estimated near zero (σ² = 0.001) and the LRT showed no improvement (χ²(2) = 0.4, p = .82), removing it follows Matuschek et al. (2017): the data provide no evidence that participants differ in their slope. The simplified model avoids degenerate variance estimates without inflating Type I error in this case.

Challenge 2: “Your model gave a singularity warning. Doesn’t that invalidate the results?” Singularity means one variance component is at its boundary, typically because the data do not support that complexity. It does not automatically invalidate the fixed effects. The correct response is to investigate which component caused the singularity, remove it if the LRT supports it, and report the decision transparently.

Challenge 3: “You included a random slope for the between-subjects manipulation. Why?” It is not possible to have a random slope for a pure between-subjects predictor — participants are each in one condition, so there is no within-participant variation to estimate a slope on. If the model appeared to converge, the slope variance estimate is meaningless or it was absorbed into the intercept variance. This is a specification error.

Preregistration Template for Random Effects

When preregistering a mixed model experiment, specify the random effects structure explicitly:

NotePreregistration Prompts for Random Effects
  • Primary random effects structure: (e.g., “Random intercepts and slopes for condition by participant; random intercepts for stimulus.”)
  • Maximal justified structure: List all predictors that vary within each grouping factor and the corresponding random slopes.
  • Simplification sequence: “If the maximal model fails to converge or is singular: (1) remove correlation parameters, (2) remove the slope with the smallest variance component, (3) repeat until convergence.”
  • Criterion for removing a slope: “Likelihood ratio test p > .10 and variance estimate < 0.001.”
  • What will be disclosed: “Any deviation from the preregistered structure will be reported in the methods section along with the LRT result that motivated the change.”
