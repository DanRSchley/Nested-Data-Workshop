Time Structure, Fixed Effects, and Seasonal Cycles

NoteThe Time Structure Question

What happens when you ignore calendar time in a longitudinal analysis? Three things can go wrong simultaneously: a background drift (the world is gradually changing) inflates or deflates your treatment estimate; a seasonal cycle (spending is higher in December) creates patterns correlated with when treatment was assigned; and period-specific shocks (a macro event in month 15) get absorbed into the wrong parameters.

How do you know time is a confounder? Residuals from your model should have zero mean at every time point. If the residuals trend upward, you have unmodeled drift. If the residuals oscillate with a 12-month period, you have unmodeled seasonality. Both are diagnosable from simple plots.

What is the fix? At minimum, include time as a predictor — as a linear drift term, as Fourier terms for cyclical patterns, or as period fixed effects (dummy variables for every calendar period). The choice depends on how much structure you are willing to assume about the time DGP.

One Dataset, Many Models

This section works differently from most of the module. Instead of showing several separate examples, we build one realistic longitudinal dataset and run it through five progressively better specifications. The true data-generating process is fully disclosed at the start. After each model you can see exactly how much bias remains and what diagnostic reveals it — and why the next specification is better.

The setting is drawn from consumer finance. A fintech platform tracks monthly spending (£) for 120 app users over 24 months (January 2023 through December 2024). The platform introduced a voluntary Loyalty Program partway through, and the research question is: does program membership cause higher spending?

Three features of this DGP create realistic analytical challenges:

  1. A background drift — platform adoption and mild inflation push spending up by £3 per month across all users, regardless of program status.
  2. A seasonal cycle — December spending is £60 above average (holiday purchases); June is £60 below. The cycle repeats every 12 months.
  3. Staggered, non-random enrollment — higher-spending users are more likely to join the program, and a November–December marketing push concentrates enrollment in the holiday season. Both features create confounding if not addressed.

Building the Dataset

The True Data-Generating Process

TipTrue DGP Parameters
Parameter Symbol True value
Loyalty program effect \(\beta_{\text{loyalty}}\) £35
Background drift (per month) \(\beta_{\text{drift}}\) £3
Seasonal amplitude \(A\) £60
Between-person SD \(\sigma_u\) £80
Within-person residual SD \(\sigma_e\) £40
Person baseline mean \(\mu\) £500

\[ Y_{it} = \underbrace{\alpha_i}_{\text{person baseline}} + \underbrace{35 \cdot D_{it}}_{\text{loyalty effect}} + \underbrace{3 \cdot t}_{\text{background drift}} + \underbrace{60 \cos\!\left(\tfrac{2\pi\, m_t}{12}\right)}_{\text{seasonal cycle}} + \underbrace{\varepsilon_{it}}_{\text{noise}} \]

where \(t\) is the calendar month (1–24), \(m_t\) is the month of year (1–12), and \(\varepsilon_{it} \sim \mathcal{N}(0, 40^2)\).

What each term does:

  • Each row is one user–month combination. There are \(120 \times 24 = 2{,}880\) rows.
  • \(\alpha_i \sim \mathcal{N}(500, 80^2)\) is the person-level baseline — their stable spending level absent the program and at zero drift/season.
  • The loyalty term is what we want to recover. The truth is £35: program members spend £35 more per month because of the program, not because they were already higher spenders.
  • The background drift adds £3 per calendar month to everyone — a rising tide. By month 24 the average user spends £72 more than in month 1 purely from drift.
  • The seasonal term uses \(\cos(2\pi m_t / 12)\): it equals \(+1\) when \(m_t = 12\) (December, spending peak \(\mu + 60\)) and \(-1\) when \(m_t = 6\) (June, trough \(\mu - 60\)). The annual swing is £120.
Code 
set.seed(2025)

n_hh     <- 120
n_months <- 24

# ── True DGP parameters ───────────────────────────────────────────────────
true_loyalty   <- 35   # £/month causal program effect
true_trend     <- 3    # £/month background drift (platform growth + inflation)
true_amplitude <- 60   # seasonal ±£60 (Dec peak, Jun trough)
true_person_sd <- 80   # between-person SD
true_resid_sd  <- 40   # within-person noise SD

# ── Person-level baselines ────────────────────────────────────────────────
person_baselines <- rnorm(n_hh, 500, true_person_sd)

# ── Staggered enrollment via discrete-time hazard ─────────────────────────
# Each non-enrolled user has a monthly probability of joining, which is:
#   (a) higher for users with higher baseline spending, and
#   (b) boosted in November (moy=11) and December (moy=12) by a marketing campaign.
# ~65% of users will eventually enroll; the rest never do.
enroll_month <- rep(NA_integer_, n_hh)
for (hh in seq_len(n_hh)) {
  for (m in 4:22) {
    moy <- ((m - 1L) %% 12L) + 1L
    p_base    <- 0.025                                               # 2.5% base monthly hazard
    p_person  <- max(0, (person_baselines[hh] - 500) / 80) * 0.025  # high spenders more likely
    p_holiday <- if (moy %in% c(11L, 12L)) 0.05 else 0             # holiday marketing boost
    p         <- min(p_base + p_person + p_holiday, 0.15)
    if (runif(1) < p) { enroll_month[hh] <- m; break }
  }
}

# ── Build the panel ────────────────────────────────────────────────────────
df <- expand_grid(person = seq_len(n_hh), month = seq_len(n_months)) |>
  mutate(
    month_of_year = ((month - 1L) %% 12L) + 1L,
    cos_12 = cos(2 * pi * month_of_year / 12),  # Fourier basis for 12-month cycle
    sin_12 = sin(2 * pi * month_of_year / 12),
    enroll_m = enroll_month[person],
    loyalty  = as.integer(!is.na(enroll_m) & month >= enroll_m),
    # True outcome components (exposed for diagnostics)
    person_component   = person_baselines[person],
    drift_component    = true_trend * month,
    seasonal_component = true_amplitude * cos_12,
    true_y = person_component + drift_component + seasonal_component +
             true_loyalty * loyalty,
    # Observed spending
    noise    = rnorm(n(), 0, true_resid_sd),
    spending = true_y + noise,
    person_f = factor(person)
  )

cat("Users enrolled by end of study:", sum(!is.na(enroll_month)),
    "/", n_hh, sprintf("(%.0f%%)\n", 100 * mean(!is.na(enroll_month))))
Users enrolled by end of study: 62 / 120 (52%)

Why Time Confounds Treatment Estimates

Person-level confound. Higher-spending users are more likely to enroll. A naïve comparison conflates the program effect with the pre-existing spending advantage of the joiners.

Background drift confound. Enrollment is staggered: higher-spending users enroll earlier (months 4–10). Because spending drifts up by £3/month for everyone, a person who enrolled in month 5 has 19 post-enrollment months concentrated in the later, higher-spending part of the window. Their within-person “before vs. after” comparison absorbs the drift as if it were a program effect.

Seasonal confound. The November–December marketing push concentrates enrollment in the highest-spending months. Post-enrollment months 1–2 of the following year are the lowest-spending months. Ignoring the cycle creates a timing-based artifact.

All three confounds are visible in residuals and diagnosable before looking at a parameter table.

Diagnostic Helper

We use three plots repeatedly — one after every model — to read off what time-based problems remain. The function below generates that standard dashboard.

Code 
# ── A consistent 3-panel diagnostic dashboard ─────────────────────────────
# trend_ok / seasonal_ok: TRUE once the confound is absorbed
show_diag <- function(model_obj, trend_ok = FALSE, seasonal_ok = FALSE) {

  resids <- residuals(model_obj)

  ok_col   <- "#2d6a4f"   # green = absorbed
  warn_col <- "#cb181d"   # red   = still present
  ci_b     <- qnorm(0.975) / sqrt(n_months)

  # ── Panel 1: residuals vs. calendar month (drift check) ─────────────────
  trend_sub <- if (trend_ok) "✓ Background drift absorbed"
               else          "✗ Background drift not captured"
  p_trend <- df |>
    mutate(resid = resids) |>
    group_by(month) |>
    summarise(mr = mean(resid), .groups = "drop") |>
    ggplot(aes(x = month, y = mr)) +
    geom_hline(yintercept = 0, linetype = "dashed", color = "grey60") +
    geom_line(linewidth = 1.1,
              color = if (trend_ok) ok_col else warn_col) +
    { if (!trend_ok) geom_smooth(method = "lm", se = FALSE,
                                 color = warn_col, linetype = "dotted",
                                 linewidth = 0.8)
      else           list() } +
    scale_x_continuous(breaks = c(1,6,12,18,24),
      labels = c("J'23","J'23","J'24","J'24","D'24")) +
    labs(title = "Residuals by calendar month",
         subtitle = trend_sub, x = NULL, y = "Mean residual (£)") +
    theme_minimal(base_size = 11) +
    theme(plot.subtitle = element_text(
      color = if (trend_ok) ok_col else warn_col, size = 9.5))

  # ── Panel 2: residuals vs. month-of-year (seasonal check) ───────────────
  seas_sub <- if (seasonal_ok) "✓ Seasonal cycle absorbed"
              else             "✗ Seasonal cycle not captured"
  p_seas <- df |>
    mutate(resid = resids) |>
    group_by(month_of_year) |>
    summarise(mr = mean(resid), .groups = "drop") |>
    ggplot(aes(x = month_of_year, y = mr)) +
    geom_hline(yintercept = 0, linetype = "dashed", color = "grey60") +
    geom_line(linewidth = 1.1,
              color = if (seasonal_ok) ok_col else warn_col) +
    geom_point(size = 2.2,
               color = if (seasonal_ok) ok_col else warn_col) +
    scale_x_continuous(breaks = 1:12,
      labels = c("J","F","M","A","M","J","J","A","S","O","N","D")) +
    labs(title = "Residuals by month of year",
         subtitle = seas_sub, x = NULL, y = "Mean residual (£)") +
    theme_minimal(base_size = 11) +
    theme(plot.subtitle = element_text(
      color = if (seasonal_ok) ok_col else warn_col, size = 9.5))

  # ── Panel 3: ACF of panel-mean residuals ─────────────────────────────────
  panel_mr <- df |>
    mutate(resid = resids) |>
    group_by(month) |>
    summarise(mr = mean(resid), .groups = "drop") |>
    pull(mr)
  acf_r <- acf(panel_mr, plot = FALSE, lag.max = 13)
  acf_df <- tibble(lag = as.integer(acf_r$lag[-1]),
                   a   = as.numeric(acf_r$acf[-1]))
  lag12_sig <- abs(acf_df$a[acf_df$lag == 12]) > ci_b
  acf_col  <- if (!lag12_sig) ok_col else warn_col
  acf_sub  <- if (!lag12_sig) "✓ No significant lag-12 spike"
              else             "✗ Lag-12 spike → annual cycle"

  p_acf <- acf_df |>
    ggplot(aes(x = lag, y = a)) +
    geom_hline(yintercept = 0) +
    geom_hline(yintercept = c(-1, 1) * ci_b,
               linetype = "dashed", color = "#2171b5") +
    geom_segment(aes(xend = lag, yend = 0),
                 color = "#888888", linewidth = 0.8) +
    geom_segment(data = filter(acf_df, lag == 12),
                 aes(xend = lag, yend = 0),
                 color = acf_col, linewidth = 1.4) +
    geom_point(color = "#555555", size = 1.8) +
    geom_point(data = filter(acf_df, lag == 12),
               color = acf_col, size = 3) +
    scale_x_continuous(breaks = c(2,4,6,8,10,12)) +
    labs(title = "ACF of panel-mean residuals",
         subtitle = acf_sub,
         x = "Lag (months)", y = "Autocorr.") +
    theme_minimal(base_size = 11) +
    theme(plot.subtitle = element_text(color = acf_col, size = 9.5))

  p_trend | p_seas | p_acf
}

Model 3: Adding the Seasonal Cycle

A 12-month cycle is parameterised with one Fourier pair: \(\cos(2\pi m_t / 12)\) and \(\sin(2\pi m_t / 12)\).

NoteWhy Fourier Terms?

Any cycle of period \(P\) can be written as \(A \cos(2\pi t/P) + B \sin(2\pi t/P)\), which is equivalent to \(R \cos(2\pi t/P - \phi)\) where \(R = \sqrt{A^2 + B^2}\) is the amplitude and \(\phi = \arctan(B/A)\) is the peak month. Including both terms lets the data determine amplitude and phase — you do not need to specify either in advance.

In our DGP the true cycle is pure cosine (\(B = 0\), December peak), so the sine coefficient should be near zero in a correctly specified model.

Code 
m3 <- lm(spending ~ loyalty + month + cos_12 + sin_12, data = df)

Model 4: The Full Specification — Person Random Effects

Adding person random intercepts addresses the remaining confound. Now we compare each user’s spending during their enrolled months to their own spending during non-enrolled months, after removing the shared drift and seasonal cycle.

Code 
m4 <- lmer(spending ~ loyalty + month + cos_12 + sin_12 + (1 | person_f),
           data = df)

person_sd_est  <- as.data.frame(VarCorr(m4)) |>
  filter(grp == "person_f") |> pull(sdcor)
resid_sd_est   <- sigma(m4)

bind_rows(
  tidy(m4, effects = "fixed") |>
    filter(term %in% c("loyalty", "month", "cos_12", "sin_12")) |>
    mutate(true_value = c(true_loyalty, true_trend, true_amplitude, 0),
           parameter  = c("Loyalty effect (£)", "Background drift (£/month)",
                          "Seasonal cosine (£)", "Seasonal sine (£)")),
  tibble(term = "σ_person", estimate = person_sd_est, std.error = NA_real_,
         statistic = NA_real_, p.value = NA_real_,
         true_value = true_person_sd, parameter = "Person SD (£)"),
  tibble(term = "σ_residual", estimate = resid_sd_est, std.error = NA_real_,

Practical Guide: Which Diagnostic, When?

Run these five checks in order whenever you receive a new longitudinal dataset:

Five-step diagnostic sequence for longitudinal time structure
Step Plot or test What you are looking for Remedy
1 Mean outcome vs. calendar time Upward/downward slope → background drift present Add month as linear (or polynomial) predictor
2 Mean outcome vs. time-of-year Repeated wave pattern → seasonal cycle present Add Fourier sin/cos terms or seasonal dummies
3 Mean residuals vs. calendar time Still drifts after controls → drift not fully captured Add higher-order polynomial or period dummies
4 Mean residuals vs. time-of-year Still waves after controls → seasonality not captured Add Fourier terms or seasonal dummy variables
5 ACF of panel-mean residuals Spike at lag k → k-period autocorrelation remaining Model residual autocorrelation (Part 5: AR structures)
WarningReviewer Challenge

What a skeptical reviewer would say: “You control for a linear background drift, but what if the drift is nonlinear? A quadratic acceleration or a structural break in month 12 would not be captured. Your loyalty estimate could absorb a nonlinear spending surge that happened to coincide with program launch.”

Observable warning sign: After adding a linear drift term, the residuals vs. calendar month plot still shows a curve — not flat but U-shaped or accelerating.

What claim survives: The direction of the loyalty effect is likely correct. The magnitude depends on how well the parametric time model matches the true time structure. Period fixed effects (Model 5) provide a robustness check with no parametric assumptions about time shape.

Setting the Stage for Growth Curve Models

Everything in this section treated time as a confounder to control. The next section, Growth Curve Models, treats time as the phenomenon of interest: how does each person’s trajectory unfold, and why do trajectories differ across people?

The diagnostic toolkit introduced here applies directly to growth curve models. When you move to random slopes and nonlinear trajectories, the same residual plots will tell you whether your trajectory model has captured the time structure correctly — or whether a remaining confound is distorting the picture.
