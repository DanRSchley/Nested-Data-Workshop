Time Structure, Fixed Effects, and Seasonal Cycles

NoteThe Time Structure Question

What happens when you ignore calendar time in a longitudinal analysis? Three things can go wrong simultaneously: a background drift (the world is gradually changing) inflates or deflates your treatment estimate; a seasonal cycle (spending is higher in December) creates patterns correlated with when treatment was assigned; and period-specific shocks get absorbed into the wrong parameters.

How do you know time is a confounder? Residuals from your model should have zero mean at every time point. If the residuals slope upward, you have unmodeled drift. If they oscillate with a 12-month period, you have unmodeled seasonality. Both are diagnosable from simple plots.

What is the fix? Include time as a predictor — as a linear drift term, Fourier terms for cyclical patterns, or period fixed effects (one dummy per calendar period). The choice depends on how much parametric structure you are willing to assume about the time DGP.

One Dataset, Many Models

This section works differently from most of the module. We build one realistic longitudinal dataset, disclose the true data-generating process completely, then run it through five progressively better specifications. Each model section follows the same five-step inferential workflow:

  1. Assumptions — what does this model assume about the data?
  2. Pre-fit checks — what can we verify before fitting?
  3. Fitting the model — code and key output
  4. Against the DGP — how well does this model recover the truth?
  5. Interpreting the results — what do the coefficients mean, and what errors would we make stopping here?

All residual diagnostic plots use the same y-axis scale, so the shrinking of residuals across models is directly visible.

The True Data-Generating Process

A fintech app tracks monthly spending ($) for 120 US users over 24 months (January 2023 through December 2024). The platform introduced a voluntary Loyalty Program partway through, and the research question is: does program membership cause higher spending?

TipTrue DGP Parameters
Parameter Symbol True value
Loyalty program effect \(\beta_{\text{loyalty}}\) $35
Background drift (per month) \(\beta_{\text{drift}}\) $3
Seasonal amplitude \(A\) $60
Between-person SD \(\sigma_u\) $80
Within-person residual SD \(\sigma_e\) $40
Person baseline mean \(\mu\) $500

\[ Y_{it} = \underbrace{\alpha_i}_{\text{person baseline}} + \underbrace{35 \cdot D_{it}}_{\text{loyalty effect}} + \underbrace{3 \cdot t}_{\text{background drift}} + \underbrace{60 \cos\!\left(\tfrac{2\pi\, m_t}{12}\right)}_{\text{seasonal cycle}} + \underbrace{\varepsilon_{it}}_{\text{noise}} \]

where \(t\) is the calendar month (1–24), \(m_t\) is the month of year (1–12), and \(\varepsilon_{it} \sim \mathcal{N}(0, 40^2)\).

  • Each row is one user–month. There are \(120 \times 24 = 2{,}880\) rows.
  • \(\alpha_i \sim \mathcal{N}(500, 80^2)\): the person’s stable monthly baseline spending.
  • Background drift (\(+\$3\)/month): platform growth and inflation lift everyone’s spending over the 24 months, totalling +$72 by the end regardless of program status.
  • Seasonal cycle: December spending is $60 above the monthly average; June is $60 below — a $120 annual swing.
  • Enrollment is staggered and non-random: higher-spending users are more likely to join; a November–December marketing push concentrates enrollment in the highest-spending months. Both create confounding.
Code 
set.seed(2025)

n_hh     <- 120
n_months <- 24

# True DGP parameters
true_loyalty   <- 35   # causal program effect ($/month)
true_trend     <- 3    # background drift ($/month)
true_amplitude <- 60   # seasonal amplitude ($)
true_person_sd <- 80   # between-person SD ($)
true_resid_sd  <- 40   # within-person residual SD ($)

# Person baselines
person_baselines <- rnorm(n_hh, 500, true_person_sd)

# Staggered enrollment:
#   (a) higher-spending users enroll earlier
#   (b) Nov/Dec marketing campaign doubles enrollment probability
enroll_month <- rep(NA_integer_, n_hh)
for (hh in seq_len(n_hh)) {
  for (m in 4:22) {
    moy       <- ((m - 1L) %% 12L) + 1L
    p_base    <- 0.025
    p_person  <- max(0, (person_baselines[hh] - 500) / 80) * 0.025
    p_holiday <- if (moy %in% c(11L, 12L)) 0.05 else 0
    p         <- min(p_base + p_person + p_holiday, 0.15)
    if (runif(1) < p) { enroll_month[hh] <- m; break }
  }
}

df <- expand_grid(person = seq_len(n_hh), month = seq_len(n_months)) |>
  mutate(
    month_of_year      = ((month - 1L) %% 12L) + 1L,
    cos_12             = cos(2 * pi * month_of_year / 12),
    sin_12             = sin(2 * pi * month_of_year / 12),
    enroll_m           = enroll_month[person],
    loyalty            = as.integer(!is.na(enroll_m) & month >= enroll_m),
    person_component   = person_baselines[person],
    drift_component    = true_trend * month,
    seasonal_component = true_amplitude * cos_12,
    true_y             = person_component + drift_component +
                         seasonal_component + true_loyalty * loyalty,
    noise              = rnorm(n(), 0, true_resid_sd),
    spending           = true_y + noise,
    person_f           = factor(person)
  )

cat(sum(!is.na(enroll_month)), "of", n_hh,
    sprintf("users enrolled (%.0f%%)\n", 100 * mean(!is.na(enroll_month))))
62 of 120 users enrolled (52%)

Fitting All Models and Setting a Common Y-Axis

Code 
# 3-panel residual dashboard used after every model.
# trend_ok / seasonal_ok drive the green/red colour coding.
# y_lim is shared across all calls so residual shrinkage is visible.

show_diag <- function(model_obj,
                      trend_ok    = FALSE,
                      seasonal_ok = FALSE,
                      y_lim       = global_y) {

  resids  <- residuals(model_obj)
  ok_col  <- "#2d6a4f"
  bad_col <- "#cb181d"
  ci_b    <- qnorm(0.975) / sqrt(n_months)

  make_sub <- function(ok, label_yes, label_no)
    if (ok) paste0("✓ ", label_yes) else paste0("✗ ", label_no)

  # Panel 1 — mean residuals by calendar month
  p1 <- df |> mutate(r = resids) |>
    group_by(month) |> summarise(mr = mean(r), .groups = "drop") |>
    ggplot(aes(x = month, y = mr)) +
    geom_hline(yintercept = 0, linetype = "dashed", color = "grey60") +
    geom_line(linewidth = 1.1,
              color = if (trend_ok) ok_col else bad_col) +
    { if (!trend_ok) list(
        geom_smooth(method = "lm", se = FALSE, linetype = "dotted",
                    color = bad_col, linewidth = 0.8))
      else list() } +
    coord_cartesian(ylim = y_lim) +
    scale_x_continuous(breaks = c(1,6,12,18,24),
      labels = c("J'23","Jn'23","J'24","Jn'24","D'24")) +
    labs(title = "Residuals by calendar month",
         subtitle = make_sub(trend_ok,
           "Background drift absorbed",
           "Background drift not captured"),
         x = NULL, y = "Mean residual ($)") +
    theme_minimal(base_size = 11) +
    theme(plot.subtitle = element_text(
      color = if (trend_ok) ok_col else bad_col, size = 9.5))

  # Panel 2 — mean residuals by month-of-year
  p2 <- df |> mutate(r = resids) |>
    group_by(month_of_year) |> summarise(mr = mean(r), .groups = "drop") |>
    ggplot(aes(x = month_of_year, y = mr)) +
    geom_hline(yintercept = 0, linetype = "dashed", color = "grey60") +
    geom_line(linewidth = 1.1,
              color = if (seasonal_ok) ok_col else bad_col) +
    geom_point(size = 2.2,
               color = if (seasonal_ok) ok_col else bad_col) +
    coord_cartesian(ylim = y_lim) +
    scale_x_continuous(breaks = 1:12,
      labels = c("J","F","M","A","M","J","J","A","S","O","N","D")) +
    labs(title = "Residuals by month of year",
         subtitle = make_sub(seasonal_ok,
           "Seasonal cycle absorbed",
           "Seasonal cycle not captured"),
         x = NULL, y = "Mean residual ($)") +
    theme_minimal(base_size = 11) +
    theme(plot.subtitle = element_text(
      color = if (seasonal_ok) ok_col else bad_col, size = 9.5))

  # Panel 3 — ACF of panel-mean residuals
  panel_mr <- df |> mutate(r = resids) |>
    group_by(month) |> summarise(mr = mean(r), .groups = "drop") |>
    pull(mr)
  acf_r  <- acf(panel_mr, plot = FALSE, lag.max = 13)
  acf_df <- tibble(lag = as.integer(acf_r$lag[-1]),
                   a   = as.numeric(acf_r$acf[-1]))
  lag12_ok  <- abs(acf_df$a[acf_df$lag == 12]) <= ci_b
  acf_col   <- if (lag12_ok) ok_col else bad_col
  acf_sub   <- if (lag12_ok) "✓ No lag-12 spike"
               else           "✗ Lag-12 spike (annual cycle)"

  p3 <- acf_df |>
    ggplot(aes(x = lag, y = a)) +
    geom_hline(yintercept = 0) +
    geom_hline(yintercept = c(-1,1)*ci_b, linetype="dashed", color="#2171b5") +
    geom_segment(aes(xend=lag, yend=0), color="grey60", linewidth=0.7) +
    geom_point(color="grey50", size=1.8) +
    geom_segment(data=filter(acf_df, lag==12),
                 aes(xend=lag, yend=0), color=acf_col, linewidth=1.5) +
    geom_point(data=filter(acf_df, lag==12), color=acf_col, size=3.5) +
    scale_x_continuous(breaks=c(2,4,6,8,10,12)) +
    labs(title = "ACF of panel-mean residuals",
         subtitle = acf_sub,
         x = "Lag (months)", y = "Autocorr.") +
    theme_minimal(base_size = 11) +
    theme(plot.subtitle = element_text(color = acf_col, size = 9.5))

  p1 | p2 | p3
}

Model 1: Naïve Pooled Regression

Step 1 — What this model assumes

WarningModel 1 Assumptions
  1. Independence: Each of the 2,880 user-month rows is an independent draw. Spending by user 47 in March is unrelated to their spending in April.
  2. No omitted variables: Nothing predicts both program enrollment and spending except what is already in the model.
  3. No time trend: Expected spending is constant across all 24 months — no background drift, no seasonal pattern.
  4. No person-level heterogeneity: All users have the same baseline spending; the only thing that differs is loyalty status.

All four are violated here. This model is a deliberate starting point — not a defensible analysis.

Step 2 — Pre-fit checks

The three diagnostic plots above already show the violations: - Average spending slopes upward → background drift exists (assumption 3 fails) - Spending cycles with a ±$60 annual amplitude → seasonal pattern exists (assumption 3 fails) - Future enrollees spend more before enrollment → person-level heterogeneity correlated with enrollment (assumption 4 and 2 fail)

Step 3 — Fitting the model

Step 5 — Interpreting the results

The loyalty estimate is roughly $50–60 — far above the true $35. Three biases are compounding:

  • Person selection: higher-spending users enrolled, so loyal users look wealthier than they are relative to the program.
  • Drift absorption: enrolled users accumulate more post-enrollment months in the later, higher-drift portion of the window. The model reads the rising tide as a loyalty benefit.
  • Seasonal absorption: enrollment peaks in November–December, the highest-spending months. The model reads holiday spending as a loyalty benefit.

What you would wrongly conclude: “Loyalty program membership increases monthly spending by $50+.” What is actually true: the causal effect is $35.

Model 2: Controlling for Background Drift

Step 1 — What this model assumes

WarningModel 2 Assumptions (new, on top of Model 1)
  1. (Inherits all Model 1 assumptions except the “no time trend” one)
  2. Linear drift: The background increase in spending is constant at exactly $k/month — it does not accelerate, decelerate, or experience any structural breaks across the 24-month window.

The seasonal cycle assumption is still violated. This model removes one confound but not both time-based confounds.

Step 2 — Pre-fit checks

The left panel from Model 1’s diagnostic above shows a clear upward slope in calendar-month residuals — a textbook symptom of unmodeled linear drift. Adding month as a predictor addresses this directly.

What you would wrongly conclude: “Loyalty program membership increases spending by ~$40–45 after accounting for overall platform growth.” What is actually true: the causal effect is still $35.

Model 3: Capturing the Seasonal Cycle

Step 1 — What this model assumes

WarningModel 3 Assumptions (new, on top of Model 2)
  1. (Inherits drift and independence assumptions from Model 2)
  2. Annual periodicity: The seasonal cycle repeats exactly every 12 months and can be represented by a single Fourier pair.
  3. Single harmonic: One cosine + one sine term at frequency 1/12 per month captures all meaningful periodic variation — there are no quarterly or weekly sub-cycles.

The person-level confound assumption is still violated. Higher-spending users are still more likely to enroll, but this model cannot remove that between-person bias.

Step 2 — Pre-fit checks

The middle and right panels from Model 2 are diagnostic: the seasonal wave (\(\approx \pm\$60\)) and the lag-12 ACF spike both persist after controlling for drift. This motivates the Fourier terms.

NoteWhy Two Terms (Cosine + Sine)?

Any single-frequency cycle can be written as: \[f(t) = A\cos\!\left(\tfrac{2\pi m_t}{12}\right) + B\sin\!\left(\tfrac{2\pi m_t}{12}\right) = R\cos\!\left(\tfrac{2\pi m_t}{12} - \phi\right)\] where \(R = \sqrt{A^2 + B^2}\) is the amplitude and \(\phi = \arctan(B/A)\) is the phase (peak month). Including both terms lets OLS determine amplitude and peak month from the data without you specifying either. In our DGP the true cycle is pure cosine (\(B = 0\), December peak), so the sine coefficient should estimate near zero.

Step 3 — Fitting the model

Model 4: The Full Specification — Person Random Effects

Step 1 — What this model assumes

WarningModel 4 Assumptions (new, on top of Model 3)
  1. (Inherits drift, Fourier, and independence assumptions from Model 3)
  2. Normal person random effects: Each user’s stable baseline spending \(\alpha_i\) is drawn from \(\mathcal{N}(0, \sigma_u^2)\).
  3. Independence of person effects and predictors: After conditioning on the drift, seasonal terms, and loyalty status, a user’s random intercept is uncorrelated with the loyalty predictor. This is the exchangeability assumption — the program was not assigned based on unmeasured time-varying characteristics.
  4. Within-person residual independence: After removing person effects, the month-to-month residuals within a person are exchangeable — no remaining autocorrelation.

This is the first model that is correctly specified for our DGP. All four assumptions hold by construction because we simulated the data.

Step 2 — Pre-fit checks

The person-level selection check shown in the pre-modeling section confirmed: future enrollees spent more before enrolling. Model 3’s loyalty estimate is still inflated (see above), even though time is correctly specified. The culprit is between-person confounding — exactly what person random effects address.

The test: does the loyalty coefficient change when person random effects are added? If yes, the between-person contrast was driving part of the Model 3 estimate.

Model 5: Period Fixed Effects (Month Dummies)

Step 1 — What this model assumes

WarningModel 5 Assumptions
  1. Each calendar month has its own intercept, absorbing all calendar-period effects — no parametric shape assumed for the time function.
  2. Each person has their own intercept (person dummies), absorbing all stable between-person differences.
  3. Loyalty effect is homogeneous: The program effect is the same for all users in all months. No user-specific or time-varying treatment effect.
  4. Strict exogeneity: After removing person and month fixed effects, loyalty status is uncorrelated with the residual.

Model 5 is more robust to misspecification of the time structure than Model 4 (no assumption of linearity or periodicity), but less efficient (23 extra parameters for month dummies vs. 3).

Step 2 — Pre-fit checks

Model 4 already passes all residual diagnostics — this model serves as a robustness check, not a correction. The question is whether relaxing the parametric time assumption changes the loyalty estimate materially.

Practical Guide: Diagnostic Sequence

When you encounter a new longitudinal dataset, run these five checks in order:

Five-step diagnostic sequence for longitudinal time structure.
Step Plot or check What you are looking for Remedy
1 Mean outcome by calendar month Upward or downward slope → background drift present Add calendar month as a linear predictor
2 Mean outcome by month-of-year Repeated wave → seasonal cycle present Add Fourier sin/cos or season-of-year dummies
3 Mean residuals by calendar month Still drifts after controls → drift not fully captured Add polynomial trend or period dummies
4 Mean residuals by month-of-year Still waves after controls → seasonality not captured Add Fourier terms or seasonal dummies
5 ACF of panel-mean residuals Spike at lag k → k-period autocorrelation remaining Model residual autocorrelation (Part 5: AR structures)
WarningReviewer Challenge

What a skeptical reviewer would say: “You control for a linear background drift, but what if the drift is nonlinear — accelerating in the second year or interrupted by a market shock in month 14? Your loyalty estimate could absorb a nonlinear surge that happened to coincide with program rollout.”

Observable warning sign: After adding a linear drift term, residuals vs. calendar month show a curve rather than a flat line.

What claim survives: Direction is likely correct. Magnitude depends on how closely the parametric time model matches the true DGP. Model 5 (period FE) is the robustness check — if it agrees with Model 4, the parametric assumption is not driving the finding.
